## 三、核心缺陷修复：外出历练无 LLM 时 500

### 根因
`src/server/lib/dungeon/service_v2.ts` 的 `callAI()` 直接调用 `generateAiObject()`，在**未配置 LLM** 时，链路
`resolveModel → resolveServerRoute → pickHighestWeightLlmRoute([])` 会抛出 `'No LLM routes to pick from.'`，
未捕获 → 接口 500。而角色生成（`CharacterGenerator`）已有模板降级路径，唯独副本没有，属功能遗漏。

### 修复
在 `callAI()` 顶部加入降级守卫，并新增 `buildTemplateRound()` 生成符合窥渊录世界观的副本回合：

```ts
private async callAI(state: DungeonState): Promise<DungeonRound> {
  if (!hasAnyServerLlmProviderConfigured()) {
    console.warn('[DungeonService] 未配置 LLM Provider，使用内置模板生成副本回合');
    return this.buildTemplateRound(state);
  }
  // ...原 AI 逻辑不变
}
```

`buildTemplateRound` 产出：
- **场景**：随 `mapNode.name` + 当前回合渐进（三套克苏鲁场景变体轮换），末回合收束。
- **三个抉择**（低/中/高险），成本复用引擎归一化函数 `calculateDungeonStatLoss`（hp_loss，返回比例小数）/ `calculateDungeonResourceCost`（spirit_stones/cultivation_exp，返回具体数值）。
- `acquired_items: []`（奖励由后续流程兜底）+ 递增 `internal_danger_score`。

> 实现要点：`calculateDungeonResourceCost` 签名是 `{type, realm, difficulty, rank}`（rank=minor/standard/major），返回**数值**；hp_loss 须用 `calculateDungeonStatLoss`。初次实现误用已纠正并通过测试。

### 边界
- 配置了 LLM 时完全走原 AI 路径，行为零改动。
- 未改动任何引擎 ID / schema 判别值 / 存档格式。
